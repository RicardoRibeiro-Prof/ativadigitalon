URL e URI: entenda cada parte de um endereço da Web

13 minutos de leituraPor Equipe Código em Sala15 de setembro de 2026
Compartilhe este conteúdo
WhatsAppFacebook

URL é o endereço que informa onde um recurso está e como acessá-lo. Em https://codigoemsala.com.br/artigos/url-uri-endereco-web.html, por exemplo, cada trecho tem uma função: https indica o esquema de acesso, codigoemsala.com.br identifica o host e o restante aponta o caminho do recurso.

Entender uma URL ajuda a navegar com mais segurança, desenvolver sites, criar APIs, interpretar links e compreender melhor DNS e HTTP e HTTPS. Neste artigo, vamos desmontar um endereço da Web peça por peça.

Base técnica e bibliográfica. A sintaxe genérica de URI segue o RFC 3986. Como apoio conceitual, usamos Kurose e Ross e Gourley, Totty, Sayer, Reddy e Aggarwal.

URL e URI são a mesma coisa?

Os termos aparecem juntos e frequentemente são usados como se fossem sinônimos, mas existe uma diferença conceitual. URI, Uniform Resource Identifier, é uma forma geral de identificar um recurso. URL, Uniform Resource Locator, é o tipo de identificador que também fornece uma maneira de localizar ou acessar o recurso.

Na prática cotidiana da Web, você quase sempre lida com URLs: endereços de páginas, imagens, arquivos e endpoints de APIs. O RFC 3986 define a sintaxe genérica dos URIs e organiza seus componentes principais em esquema, autoridade, caminho, consulta e fragmento.

Regra simples para começar: pense em URI como a família de identificadores e em URL como o endereço usado para chegar a um recurso.

Desmontando uma URL completa

Considere este exemplo didático:

https://www.exemplo.com:443/produtos/notebooks?marca=acer&ordem=preco#ofertas
TrechoNomeFunção
httpsScheme ou esquemaIndica como o recurso será acessado
www.exemplo.comHostIdentifica o servidor ou nome de rede
443PortaIdentifica um serviço no host
/produtos/notebooksCaminhoIdentifica o recurso dentro daquele contexto
?marca=acer&ordem=precoQueryAcrescenta dados não hierárquicos à referência
#ofertasFragmentoAponta para uma parte do recurso

1. Scheme: o começo do endereço

O esquema vem antes dos dois-pontos. Em URLs da Web, os exemplos mais conhecidos são http e https. Também existem outros esquemas de URI, como mailto:, tel: e ftp:. O esquema define regras para interpretar o restante do identificador.

2. Autoridade: onde aparece o host

Depois de // normalmente encontramos a autoridade. Ela pode conter informações de usuário, host e porta, embora credenciais em URLs devam ser evitadas. No uso comum da Web, a parte mais visível é o host, como codigoemsala.com.br.

3. Porta: qual serviço atenderá

A porta é opcional na URL. HTTPS normalmente usa a porta 443 e HTTP, a 80; quando a porta padrão é usada, o navegador não precisa exibi-la. Em desenvolvimento é comum encontrar endereços como http://localhost:3000.

4. Caminho: qual recurso queremos

O caminho vem depois da autoridade e costuma ser organizado em segmentos separados por barras. Em /artigos/dns-como-funciona.html, o caminho aponta para um recurso dentro do site. Ele não precisa corresponder literalmente a pastas físicas no servidor: aplicações podem mapear rotas para código, banco de dados ou conteúdo gerado dinamicamente.

Domínio, host e DNS: conceitos relacionados, mas diferentes

Quando digitamos codigoemsala.com.br, estamos usando um nome que pode ser resolvido pelo DNS. O navegador precisa descobrir para qual infraestrutura de rede deve encaminhar a comunicação. É aí que o Sistema de Nomes de Domínio entra.

É importante não confundir o endereço inteiro com o domínio. A URL inclui muito mais informações. Em https://codigoemsala.com.br/artigos/, o domínio é apenas uma parte do endereço.

Query string: os dados depois do ponto de interrogação

A consulta começa com ?. Ela é frequentemente formada por pares de chave e valor. Um site de busca poderia usar:

https://exemplo.com/busca?q=rede&pagina=2

Nesse caso, q=rede e pagina=2 fornecem dados adicionais ao recurso /busca. A aplicação decide o significado desses parâmetros. Eles podem controlar filtros, paginação, ordenação e outras opções.

Cuidado: dados colocados na URL podem aparecer no histórico do navegador, logs, ferramentas de análise e links compartilhados. Senhas e outros segredos não devem ser colocados em parâmetros de URL.

Fragmento: o que vem depois de #

O fragmento começa com # e identifica uma parte secundária do recurso. Ao abrir pagina.html#referencias, o navegador pode ir diretamente até um elemento com aquele identificador. Segundo a sintaxe de URI, o fragmento é separado do restante da referência; em requisições HTTP comuns, ele é tratado pelo cliente e não é enviado ao servidor como parte do alvo da requisição.

URL absoluta e referência relativa

Uma referência absoluta contém informação suficiente para identificar o recurso sem depender do endereço atual:

https://codigoemsala.com.br/artigos/dns-como-funciona.html

Já uma referência relativa depende de uma URL-base:

dns-como-funciona.html
../assets/images/capa-internet.webp
#referencias

Isso é muito usado em HTML. Dentro de um artigo deste blog, por exemplo, ../styles.css sobe um nível e encontra a folha de estilos. Referências relativas facilitam mover um conjunto de páginas dentro da mesma estrutura, mas precisam ser calculadas em relação à base correta.

Caracteres especiais e percent-encoding

URLs possuem caracteres reservados com funções sintáticas, como /, ?, # e %. Quando um octeto precisa ser representado em um componente e não pode aparecer diretamente, pode ser usado o percent-encoding: um sinal de porcentagem seguido por dois dígitos hexadecimais. O espaço, por exemplo, pode aparecer como %20 em determinados contextos.

Isso explica por que alguns endereços copiados do navegador parecem conter sequências estranhas. Não significa necessariamente erro; pode ser apenas a representação codificada de dados.

Como ler uma URL antes de clicar

Saber separar as partes de uma URL também é uma habilidade de segurança. O ponto principal é identificar corretamente o host. Um endereço como https://banco.exemplo-malicioso.com/ pertence a exemplo-malicioso.com, não a um banco chamado “banco”. Palavras colocadas antes do domínio principal podem ser apenas subdomínios criados para confundir.

Também observe o esquema. HTTPS protege a comunicação com o host apresentado pelo certificado, mas, como explicamos no artigo sobre HTTP e HTTPS, isso não garante que o conteúdo ou a empresa por trás do site seja legítima.

O que acontece depois que você digita uma URL?

De forma simplificada, o navegador interpreta a URL, identifica o host, pode consultar o DNS, estabelece a comunicação de rede, negocia proteção TLS quando HTTPS é usado e envia uma requisição HTTP para o recurso. O servidor responde, e o navegador processa HTML, CSS, JavaScript, imagens e outros recursos necessários.

Perceba como os conceitos se conectam: URL diz qual recurso queremos; DNS ajuda a encontrar o host; HTTP organiza a troca de mensagens; HTTPS protege a comunicação.

Conclusão

Uma URL não é uma sequência aleatória de caracteres. Ela possui uma estrutura previsível. Quando você reconhece esquema, host, porta, caminho, query e fragmento, fica mais fácil compreender a Web, programar aplicações e analisar links suspeitos.

Perguntas frequentes

URL e link são a mesma coisa?

Não exatamente. URL é um identificador/endereço. Link é um elemento ou referência que aponta para um destino, normalmente usando uma URL ou referência URI.

www faz parte do domínio?

www normalmente é um subdomínio/hostname convencional. Um site pode funcionar com ou sem ele, dependendo da configuração de DNS e do servidor.

O fragmento # é enviado ao servidor?

Em uma navegação HTTP normal, não. O fragmento é processado pelo cliente depois que o recurso é obtido.

Posso colocar senha na URL?

Não é uma prática segura. URLs podem ficar registradas em histórico, logs e outros sistemas. Segredos devem usar mecanismos apropriados de autenticação e transporte.
